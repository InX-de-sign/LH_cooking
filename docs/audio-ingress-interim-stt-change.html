Audio ingress interim STT

A code-level record of the change in chatbot/audio_receiver.py. It adds progressive speech-to-text updates while preserving audio_complete as the boundary that creates one final chatbot response.

The socket reader in _handle_audio_stream() remains the ingress point. For every audio_chunk, it decodes message["audio"] and appends the resulting bytes to self.audio_queues[client_id]. The worker _process_audio_queue() owns utterance assembly and recognition.

Behavior before the change

Previous behavior

Each received packet was stored, but no STT call occurred until the client supplied {"type": "audio_complete"}. The complete marker was appended as the string "COMPLETE".

elif msg_type == "audio_complete":
    if client_id in self.audio_queues:

# _process_audio_queue()

if isinstance(item, bytes):

That ordering creates a strict batch boundary: microphone capture, transport, queueing, WAV assembly, and gSTT all wait for COMPLETE. The response path then starts only after final recognition returns.

Code added

Current behavior

Per-client state

self.interim_stt_tasks: Dict[str, asyncio.Task] = {}
self.interim_stt_pending: Dict[str, bool] = {}
self.last_interim_text: Dict[str, str] = {}

interim_stt_tasks limits each client to one ongoing HTTP recognition request. interim_stt_pending coalesces packets received during that request. last_interim_text suppresses duplicate UI updates.

New call after each chunk

if isinstance(item, bytes):
    audio_chunks.append(item)
    self._start_interim_stt(audio_chunks, client_id, websocket)

This call runs after the chunk enters the utterance buffer. It does not remove chunks and does not invoke OpenAI or TTS.

def _start_interim_stt(self, audio_chunks, client_id, websocket):
    task = self.interim_stt_tasks.get(client_id)
    if task and not task.done():
        self.interim_stt_pending[client_id] = True
        return

    self.interim_stt_pending[client_id] = False
    self.interim_stt_tasks[client_id] = asyncio.create_task(
        self._recognize_interim_snapshot(audio_chunks, client_id, websocket)
    )

async def _recognize_interim_snapshot(self, chunks, client_id, websocket):
    wav_bytes = self._combine_to_proper_wav(list(chunks), client_id)
    if not wav_bytes or len(wav_bytes) < 10000:
        return

    text = await self._google_stt(wav_bytes)
    if text and text != self.last_interim_text.get(client_id):
        self.last_interim_text[client_id] = text
        await websocket.send_json({
            "type": "stt_interim", "text": text, "client_id": client_id,
        })

    # In finally: schedule a fresh snapshot after any queued chunks.
    if self.interim_stt_pending.pop(client_id, False):
        asyncio.get_running_loop().call_soon(
            self._start_interim_stt, chunks, client_id, websocket
        )

Rationale

  1. Raw chunks are not safe STT input. Individual packets can be raw PCM or fragments of WAV data. _combine_to_proper_wav() normalizes the accumulated bytes into a complete WAV container using the client sample rate and channel settings.
  2. The installed gSTT adapter is batch-only. optimized_voice.py writes its input to a temporary WAV file and calls recognizer.recognize_google(...). It cannot keep a single recognition session open while new audio arrives.
  3. Snapshots provide progressive feedback without invalid audio. The receiver makes an asynchronous request using the audio captured so far. The client receives changed results as stt_interim.
  4. One in-flight request avoids request storms. If packets arrive faster than gSTT replies, the receiver marks the latest state pending rather than starting a request per packet. Once the current task ends, it processes the newest buffer.
  5. COMPLETE remains the turn boundary. Interim text is display-only. The existing final STT call and _process_with_openai_and_stream() remain in the COMPLETE branch, so the assistant does not answer multiple times while the user is speaking.

Not true bidirectional streaming STT

This reduces perceived transcription latency, but it is not word-by-word Google Cloud streaming recognition. For that, replace SpeechRecognition.recognize_google() in optimized_voice.py with a provider SDK that supports a persistent streaming connection, then feed the raw PCM frames to that session and consume interim/final events from it.

Protocol and lifecycle effects

  • No ESP32 ingress message changes are required. Existing audio_chunk and audio_complete messages are retained.
  • Clients that display partial transcription should handle stt_interim. Existing handling of stt_result remains the final transcript.
  • Connection cleanup cancels the interim task and removes pending/transcript state, alongside the existing queue and processing-task cleanup.
  • The minimum snapshot threshold remains 10,000 bytes because _google_stt() rejects smaller inputs; early packets below that size incur no network recognition request.
