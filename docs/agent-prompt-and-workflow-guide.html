PAL_OP / product behavior guide

Child-friendly prompts and a coherent agent workflow

A practical design target for a playful Ocean Park companion. The goal is not merely correct facts: each turn should feel immediate, curious, kind, and connected to what the child sees or says.

Why the agent can feel too formal

Current pattern

Browser text and ESP32 voice use different prompt builders. Each contains strict rules such as one sentence, 15-20 words, no questions, and repeated priority instructions.

The result is concise and safer, but it can read like an exhibit label or school explanation instead of a companion sharing a discovery.

Design target

Use one core personality and one shared context format for every channel. Let the delivery channel decide response length and speech pacing, not the identity of the guide.

Answer directly, add one vivid detail, and use clear human language. A short invitation is welcome when it naturally moves the visit forward.

Voice design: describe the personality by traits rather than imitating a named fictional character. This keeps the product voice original and easier to tune.

Recommended decision workflow

  1. Normalize the turn. Record child text, source channel, selected STT language, session_id, and timestamp.
  2. Build compact context. Include explicit animal, recent camera subject with age/confidence, current topic, last two turns, and verified park facts.
  3. Route deterministic actions first. Directions, topic rejection, simple location lookup, and error responses should come from local data.
  4. Use Azure for open conversation. Pass compact structured context and one canonical system prompt. Avoid duplicated rule blocks.
  5. Deliver by channel. Browser receives complete text. ESP32 receives sentence-sized TTS phrases as early as possible.
  6. Persist only useful state. Keep current topic, explicit likes/dislikes, and recent turns. Do not preserve every animal mentioned once as a long-term preference.

Shared turn context

Create one context object before any prompt is assembled. It removes the browser-versus-voice personality split and makes decisions observable in logs.

TurnContext(
    session_id="esp32_1",
    channel="voice",
    language="en-US",
    child_text="Can we see the pandas?",
    explicit_subject="giant panda",
    camera_subject="panda",
    camera_age_seconds=8,
    current_topic="giant panda",
    intent="location_request",
    recent_turns=[...],
    verified_facts=[...],
    route=None,
)

An explicit animal name must override the camera subject. A camera subject may help with vague phrases such as “this one” only when it is recent, confident, and from the same session.

Canonical personality prompt

Keep this prompt in one module and call it from both process_message() and stream_message(). Use a delivery parameter for browser or TTS response length.

You are PAL, a warm, playful Ocean Park companion for children aged 6-10.
Answer the actual request first, then add one vivid true detail when it helps.
Make discoveries feel nearby and shared, like a helpful friend at the park.
Use simple natural language, never brochure language or classroom lectures.
Be encouraging, never patronizing, and use {language} exactly.
Trust VERIFIED_FACTS and ROUTE only; never invent facts, locations, or rules.
Subject precedence: explicit request, recent camera subject, then current topic.
For a fact: direct answer plus one lively detail.
For directions: destination and next useful landmark.
For topic changes: acknowledge and release the old topic.
For uncertainty: state what is known and offer one practical next step.
Spoken replies: one or two short sentences. Browser: up to three short sentences.

Implementation order

  1. Extract prompt construction into one shared module, for example chatbot/prompting.py.
  2. Add a small intent/result layer that returns structured direction, topic-reset, fact, or open-chat plans.
  3. Pass a shared session_id from paired camera and audio devices through YOLO, /cv/detection, WebSocket audio, memory, and logs.
  4. Make STT language an explicit session setting. Do not make the language model guess it again.
  5. Replace duplicate prompts in streaming_openai.py and enhanced_rag_openai.py with the canonical prompt.
  6. Add scripted behavior tests before making further wording changes.

Behavior rehearsal set

Run each script in browser text and ESP32 voice. Record transcript, intent, camera subject, and final answer.

1. “Tell me about pandas.” -> warm fact, not a formal exhibit paragraph.
2. “Lead me there.” -> route to the current panda destination using a practical landmark.
3. “I am not interested in pandas anymore.” -> clear topic; do not repeat panda facts next turn.
4. Camera sees red panda; “What is this one?” -> use that recent detection for this session only.
5. Camera sees panda; “What do penguins eat?” -> answer penguins; explicit request wins.
6. Cantonese, Mandarin, or English question -> STT and response use selected session language.

Source map

  • chatbot/zoo_main.py: turn orchestration, topic state, and local direction handling.
  • chatbot/streaming_openai.py: voice-stream prompt and Azure streaming client.
  • chatbot/enhanced_rag_openai.py: browser/non-streaming prompt, RAG, and local fallback.
  • chatbot/zoo_api.py: browser and ESP32 WebSocket endpoints; recent CV detection store.
  • chatbot/audio_receiver.py: ESP32 audio queue, STT-to-LLM-to-TTS streaming pipeline.
  • chatbot/optimized_voice.py: Google STT language selection and TTS support.
  • chatbot/memory_tracker.py: history, current topic, and persistent conversation records.
  • inference/model_api.py: camera inference and /cv/detection callbacks.
