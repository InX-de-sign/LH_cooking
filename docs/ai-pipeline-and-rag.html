Offline reference

How a question becomes an answer

The pipeline after the model switch and the retrieval rebuild — what each hop does, what the rework fixed, and the ranked list of what is still wrong.

Where things stand

The model switch and the retrieval rebuild are done and verified live

  • gpt-5-mini on the HKUST proxy, reasoning_effort=minimal, answering in ~1.4–2.2 s — measurably faster than the gpt-4o-mini it replaced.
  • 478 facts across 48 exhibits and 35 species, up from LIKE '%name%' over 8 rows.
  • Hierarchical memory: visit → episode → turn, with a ledger so "tell me more" never repeats itself.
  • Grounded: empty retrieval produces an honest "I'm not sure", not an invented exhibit.

Nothing is committed yet. The working tree holds 13 modified files and 4 new ones.

The pipeline

Nine hops from microphone to speaker

Modules in chatbot/. Hops 4–6 are the part that was rebuilt.

  ESP32 mic ──▶ /ws/esp32/audio/{id} ──▶ STT ──┐
                                                 ├──▶ context_builder ──▶ gpt-5-mini ──▶ TTS ──▶ ESP32 speaker
  ESP32-CAM ──▶ YOLO ──▶ POST /cv/detection ──┘          │
                                                            ├── knowledge_base    (what it knows)
                                                            └── conversation_state (what it remembers)
1
zoo_api.py · audio_receiver.py

Audio arrives

The ESP32 audio unit streams I2S chunks over a WebSocket. Recording ends on silence rather than a fixed window.

2
optimized_voice.py · Google Speech

Speech becomes text

STT_LANGUAGES defaults to en-US alone — one round trip, no misdetection. Listing several languages scores them by recogniser confidence rather than taking the first non-empty answer.

Consequence worth knowing: with the default, Cantonese speech never reaches the model as Chinese at all. See problem 2.

3
inference/ → POST /cv/detection

The camera offers a label

YOLO posts a label such as red-panda. It is stored per client id and treated as valid for 30 s. The camera id is mapped to the audio id by CLIENT_ID_MAPPING.

4
context_builder.py · resolve_subject()

What is "it"?

The whole game for a walk-up guide. Priority order:

  1. an animal named outright in the question
  2. a pronoun ("what do they eat?") → the open episode's subject
  3. the camera detection
  4. the open episode, carried forward
  5. nothing — a park-level question

Note that 1 beats 3. Previously the camera overrode everything, so asking about capybaras while standing at the pandas got you an answer about pandas.

5
knowledge_base.py · retrieve()

Facts, not rows

The question is classified into a facet — diet, route, conservation, practical and ten others — then a cascade runs, exhausting every facet-specific source before broadening:

1. facet on the subject
2. facet on the subject's exhibit(s)     ← a species has no route facts;
3. facet park-wide                          its exhibit does
4. any facet on the subject
5. any facet on its exhibit(s)
6. FTS5 full-text search

Facts already told this visit are excluded, which is what makes a second "tell me more" produce new material.

6
context_builder.py · _render()

Four labelled layers

[VISIT]   English speaker. 12 minutes in, 6 questions.
          Already visited: Red Panda, Giant Panda.
[NOW]     Asking about the King Penguin (they named it).
          Already covered: location, diet (2 questions).
[RECENT]  Child: what do they eat?
          Guide: King penguins eat small fishes and squid.
[FACTS]   Use only these. Do not invent exhibits or numbers.
          - (route) Monkey Tree presents South Pole Spectacular: ...
[QUESTION] How do I get there?

The old prompt was one flat concatenation with nothing marking which part described now and which described earlier.

7
streaming_openai.py · config.py

The model call

completion_kwargs() emits the parameter set the deployment family needs. Rolling back to gpt-4o-mini is one environment variable.

Language is decided in Python and stated outright, never inferred by the model.

8
elevenlabs_voice.py · esp32_tts_streamer.py

Text becomes audio

ElevenLabs MP3, decoded to 16 kHz mono WAV by miniaudio, streamed back to the ESP32.

9
conversation_state.py

The turn is recorded

The exchange is written against its episode, the facet is added to the episode's coverage, and every fact used is marked delivered.

What the rework fixed

WasNowEvidence
No retrieval. LIKE '%name%' over 8 rows, gated by a hardcoded 7-animal list. The crocodile, dolphins and walruses were unreachable. 478 facts, 35 species, 48 exhibits, alias-resolved and facet-ranked. knowledge_base.py
The streaming path — the one the ESP32 uses — never called get_park_info_context(), so attractions, rides and directions were invisible to the voice bot. One retrieval path for both streaming and non-streaming. enhanced_rag_openai.py
A hit dumped all 13 columns; the prompt builder then discarded most of them by substring filter. Intent never chose what to fetch. Facet-level retrieval: the question selects the facts. retrieve()
Flat context. current_topic was a scalar every camera detection overwrote. visit → episode → turn, with computed episode summaries. conversation_state.py
Repeats itself. Nothing tracked what had already been said. Delivered-fact ledger; retrieval excludes what was already told. delivered_facts
Invented exhibits. Testing produced a confident "Red Panda Habitat" that does not exist. Empty retrieval states so explicitly; the guide admits it does not know. grounding block
English questions answered in Chinese — the prompt mentioned Cantonese unconditionally. gpt-4o-mini did this too. English-first. Chinese must be ≥35% of the letters to switch. detect_language()
max_tokens=50 on gpt-5 returns an empty string, not an error. completion_kwargs() per model family, with a budget floor. config.py
Running from chatbot/ loaded the placeholder key in chatbot/.env, gave a 401, and silently fell back to canned answers. Both .env files are loaded; placeholders are treated as unset. _load_env_files()

Problems still to fix

Ranked by how much each one costs a real visitor.

P1

The knowledge base is a mile wide and an inch deep blocking

Symptom
Ask "what do meerkats eat?" and the guide correctly says it does not know. It knows where the meerkats are and nothing else.
Measured
27 of 35 species have 3 facts or fewer, usually just a location. 29 of 35 have no diet fact at all. Only the 8 species carried over from zoo.db have real depth.
Cause
Not retrieval. park_knowledge.py describes exhibits richly and species barely; zoo.db holds only 8 species, and several of its prose columns are empty strings.
Fix
Add species rows to zoo.db for the other 27, then python knowledge_base.py --rebuild. The schema and the loader already handle them — this is data entry, not code.

Facts per facet — the shape of the gap:

location120
highlight94
overview70
route53
practical32
conservation24
nearby19

story11
habitat8

Children ask about diet and behaviour constantly. Those are the two thinnest facets in the database.

P2

Cantonese cannot reach the guide by voice decision needed

Symptom
A child speaking Cantonese to the ESP32 gets nonsense, because Google transcribes their speech as garbled English.
Cause
STT_LANGUAGES defaults to en-US alone. This was a deliberate earlier fix — the old code looped zh-HK, zh-CN, en-US and returned the first non-empty result, which meant zh-HK answered nonsense Chinese for English speech and en-US was never reached.
Consequence
The Cantonese reply path is currently reachable only from the browser text box. GUIDE_LANGUAGE_MODE has no effect on the voice path.
Decision
If English-only is the product: nothing to do — set GUIDE_LANGUAGE_MODE=en to make it explicit.
If Cantonese is wanted: set STT_LANGUAGES=en-US,zh-HK. Both are then scored by recogniser confidence, at the cost of a second sequential STT round trip on the critical path.
P3

The same animal fact is written in four places drift risk

Symptom
Ungrounded claims can still reach a visitor, through paths the [FACTS] guard does not cover.
Evidence
streaming_openai.py prompt example: "The pandas munch through 40 kilograms of bamboo every single day" — while knowledge.db says the giant panda needs 4,300–5,500 kcal/day. Both are in the model's context at once.
zoo_api.py lines 144–157 hold hardcoded greeting facts per label.
enhanced_rag_openai.py lines 623–641 hold hardcoded fallback answers, used whenever the API call fails.
Fix
Drive the CV greeting and the offline fallback from knowledge.db, and strip the concrete numbers out of the prompt examples so they teach tone rather than content.
P4

Full-text search does not work in Chinese design limit

Symptom
A Chinese question about a subject missing from the alias table retrieves nothing, where the English equivalent would fall back to full-text search.
Cause
FTS5's unicode61 tokeniser does not segment Chinese, and every fact body is English. Chinese is carried entirely by the ~40 hand-written aliases in EXTRA_ALIASES.
Fix
Short term, keep adding Chinese aliases as species are added — that is where the value is. Long term, this is the one place embeddings would genuinely beat FTS5; Qdrant is already in the compose file and text-embedding-3-small is available on the proxy.
P5

The browser client never receives camera context minor

Symptom
Testing "what animal is this?" from zoo_index.html always behaves as if no camera is attached.
Cause
zoo_api.py:212 mints a random client_id per WebSocket connection, while detections are keyed by the posted user_id. They can never match. The ESP32 path uses a fixed id and works correctly.
Fix
Let the browser send an id in the connect frame, or accept one as a query parameter, and map it the way CLIENT_ID_MAPPING does for the camera.
P6

Superseded code and unused services still in the tree tidy-up

  • memory_tracker.py — fully replaced by conversation_state.py, no longer on the request path.
  • enhanced_rag_openai.py — roughly 250 lines (extract_animal_from_message, enhanced_animal_search, build_contextual_response, get_park_info_context, _build_enhanced_prompt) now reachable only when no prompt_context is supplied, which the live paths always supply.
  • Qdrant — a container in both compose files, imported nowhere. Either use it for P4 or drop it.
  • Postgres — still running the iteration-1 museum schema (museum_objects, learning_progress, a VECTOR(1536) column). Nothing reads it; all real state is SQLite.
P7

Collective labels are registered as species cosmetic

Sharks, Rays, Reef fish, Sea cucumbers and Sea Jellies are groups, not species. They come from the animals lists on the exhibit pages. Answers read slightly oddly ("You can see the Sharks at Shark Mystique"), and they cannot carry species-level facts.

P8

No automated tests process

Everything in this document was verified by hand. The retrieval layer is unusually easy to test — resolve_subject, classify_facet and retrieve are pure functions over a fixed database, needing no API key. A table of question → expected subject and facet would catch regressions like the two found while building this: "do" classifying as a behaviour question, and "how do I get to the park?" inheriting the previously discussed animal.

P9

Park data has no freshness mechanism watch

park_knowledge.py is a hand-maintained snapshot of the Ocean Park website. It already contains time-bound copy — North Pole Encounter is described as closed from 5 January 2026 "until further notice" — and that text is now a retrievable fact. Nothing flags a stale entry, and there is no scrape date on any record.

PowerShell

curl is an alias for Invoke-WebRequest and does not accept -X, -H or -d; \ is not a line continuation. Use scripts/check_model.py, or Invoke-RestMethod, or real curl.exe with the JSON body in a file — an inline -d string is mangled by the argument parser and returns a 500.
